## 1. 整体方案设计

### 1.1 系统架构

系统采用分层架构设计，明确区分职责边界：

```
源数据提取
  ↓
合约验证与规范化
  ↓
不可变Parquet数据湖
  ↓
截至观察时点的特征工程
  ↓
受控的模型训练作业
  ↓
模型注册适配器
  ↓
批量评分存储
  ↓
只读风险/证据API + 时序路径仓库
  ↓
反诈运营研判工作台
```

**核心设计原则**：

1. **不可变性**：每一份数据、特征、模型和评分产物都具有由内容导出的版本标识
2. **可审计性**：所有操作可追溯，证据报告引用源交易ID
3. **时序安全**：特征生成严格使用半开时间区间 `[as_of - lookback, as_of)`
4. **确定性**：相同输入保证产生相同输出，支持完全可复现
5. **职责分离**：模型输出仅用于辅助决策，不自动执行止付或冻结

### 1.2 技术栈选择

| 组件 | 技术选型 | 选择理由 |
|------|---------|---------|
| **数据存储** | Parquet + DuckDB | 列式存储，高效查询，可无缝切换至对象存储 |
| **特征计算** | Pandas + DuckDB | 原型快速验证，接口可替换为Spark/Flink |
| **图谱引擎** | 自研时序路径搜索 | 满足时间约束+金额连续性，可切换至图数据库 |
| **模型训练** | scikit-learn | 可解释性强，符合金融监管要求 |
| **Web服务** | FastAPI | 高性能异步框架，自动API文档生成 |
| **前端界面** | 原生JS + D3.js | 轻量化，可视化资金图谱 |

**可扩展性**：当前实现使用本地Parquet和DuckDB提供可复现的垂直切片。接口设计支持企业级部署替换为对象存储、Kafka事件流、ClickHouse/PostgreSQL等。

### 1.3 数据流程

```
1. 数据接入（fraud-graph ingest）

3. 模型训练（fraud-graph train）
   - 5折分层交叉验证

   - 生成模型版本（如 27e53f783dde8968）

4. 批量评分（fraud-graph score）
   - 对所有账户生成风险分数
```

### 2.2 时间窗口控制机制

系统实现了严格的时序安全保证：

**半开时间区间**：
```python
# 特征生成严格使用
feature_window = [as_of - lookback, as_of)
# 例如：观察时点2025-10-01，回溯90天
# 有效窗口：[2025-07-03, 2025-10-01)
```

**防止未来信息泄露**：
- 交易边只包含观察时点之前的数据
- 标签仅用于跨文件一致性校验，绝不写入特征表
- 路径搜索仅使用时间递增的交易序列

### 2.3 防泄露机制（label_available_at）

**生产级要求**：
标签必须包含以下字段：
```
account_id           # 账户标识
label                # 风险标签（0/1）
risk_event_at        # 风险事件发生时间（预测目标）
label_available_at   # 标签可得时间（控制训练可见性）
case_id              # 案件编号（可选但强烈建议）
```

**两个时间的区别**：
- `risk_event_at`：定义预测目标（账户何时发生风险）
- `label_available_at`：控制标签在历史锚点的可见性（避免时间泄露）

**当前限制**：
- ⚠️ 提供的数据集缺少 `label_available_at` 字段
- ⚠️ 系统阻止时序模型训练，标记为 `production_eligible=false`
- ⚠️ 只能使用 `--allow-static-labels` 进行静态回溯实验

**产物目录结构**：

### 3.1 模型选择（逻辑回归）

**选择理由**：

1. **可解释性强**：系数直接对应特征贡献度，满足金融监管要求
2. **训练高效**：在极度不平衡数据上表现稳定
3. **概率校准**：输出校准良好的概率（Brier Score 0.0425）
4. **基线合格**：作为契约兼容的参考模型，可后续扩展GNN

**模型配置**：
```python

参数：class_weight='balanced'  # 处理1:187不平衡
训练模式：5-Fold Stratified Cross-Validation
```

**训练数据**：
- 样本数：11,087个账户

### 3.2 特征工程（行为+画像）

系统构建了27个特征，分为两大类：

#### 3.2.1 行为特征（22个）

**交易笔数类**：
- 总交易笔数
- 付款笔数 / 收款笔数
- 高额交易笔数（>阈值）

**交易金额类**：
- 总交易金额
- 平均交易金额 / 中位数金额
- 最大单笔金额 / 金额标准差
- 付款总额 / 收款总额

**时间模式类**：
- 首次/末次交易距离观察时点的天数
- 交易活跃天数
- 夜间交易占比（22:00-06:00）
- 周末交易占比

**交易对手类**：
- 唯一交易对手数
- 交易对手集中度（Herfindahl指数）
- 单向交易对手占比

**图结构类**：
- 入度 / 出度
- PageRank分数
- 连通分量大小

#### 3.2.2 账户画像特征（5个）

- **开户时长**：距离观察时点的天数（tenure_days）
- **地区代码**：开户地区（region_code，类别编码）
- **客户类型**：个人/企业（customer_type）
- **账户状态**：正常/冻结/注销（account_status）
- **风险等级**：历史风险评级（risk_tier，可选）

### 3.3 消融实验结果

系统训练了3组特征集的12个模型，发现了重要规律：

| 特征集 | 特征数 | AUC | Top5%召回率 | Lift | 模型数 |
|--------|--------|-----|------------|------|--------|
| **Combined** | 27个 | **0.9341** | **57.6%** | **11.51x** | 4个 |
| **Profile** | 5个 | 0.9243 | 57.6% | 11.51x | 4个 |
| **Behavior** | 22个 | 0.8162 | 15.3% | 3.05x | 4个 |

**关键发现**：

**1. 静态画像是最强信号**
```
Profile单独：AUC 0.924（仅5个特征）
    vs
Behavior单独：AUC 0.816（22个特征）

结论：账户本身属性比交易行为更具区分性
```

**解释**：涉诈账户可能在**开户阶段**就已经有明显特征（如特定地区、开户时间集中、客户类型异常等）。

**2. Combined策略是最优解**
```
Combined (0.9341) > Profile (0.9243) > Behavior (0.8162)
                     ↑                    ↑
              静态画像主导           行为特征补充
```
行为特征提供额外的1个百分点AUC增益。

**3. 反直觉发现：召回率相同**

Profile和Combined捕获的是**同一批**风险账户（Top5%召回率均为57.6%），行为特征提升了排序能力（AUC +1%），但没有发现新的风险账户。

## 4. 任务3：可疑关联账户与资金链路挖掘

### 4.1 路径搜索算法（BFS+时序约束）

系统实现了自研的时序路径搜索引擎，满足以下约束：

**算法特点**：
1. **有向图遍历**：从根账户出发，沿交易方向搜索
2. **时间单调性**：路径上的交易时间必须严格递增
3. **跳数限制**：默认最大2跳（可配置）
4. **时间间隔约束**：相邻交易的时间间隔需在合理范围内（如<30天）
5. **金额连续性**：可选配置金额占比阈值（如后续交易金额≥前序的X%）

**伪代码**：
```python
def search_temporal_paths(root_account, max_hops, max_gap_days):
    queue = [(root_account, [], None)]  # (当前节点, 路径, 最后交易时间)
    paths = []
    
    while queue:
        current, path, last_time = queue.pop(0)
        
        if len(path) >= max_hops:
            paths.append(path)
            continue
        
        # 获取当前账户的所有出边（付款交易）
        for edge in get_outgoing_edges(current):
            # 时序约束：交易时间必须晚于路径上的最后交易
            if last_time and edge.time <= last_time:
                continue
            
            # 时间间隔约束
            if last_time and (edge.time - last_time).days > max_gap_days:
                continue
            
            # 金额连续性约束（可选）
            if path and edge.amount < path[-1].amount * amount_threshold:
                continue
            
            new_path = path + [edge]
            queue.append((edge.to_account, new_path, edge.time))
    
    return paths
```

**与通用图算法的区别**：
- NetworkX/Neo4j的最短路径算法不考虑时间约束
- 本实现确保每条路径都是"可能发生的真实资金流"

### 4.2 Top-20关联账户发现

**发现策略**：
对于给定根账户，按以下规则发现关联账户：

1. **直接交易对手**（1跳）：
   - 收款方（root → account）
   - 付款方（account → root）
   - 按交易笔数或金额排序

2. **间接关联账户**（2跳）：
   - root → A → B（通过A中转到B）
   - A → root → B（root作为中转）
   - 按路径数量或金额总和排序

3. **时序过滤**：
   - 只保留观察时点之前的路径
   - 排除时间间隔过大的松散关联

4. **风险优先排序**：
   - 如果关联账户有模型分数，按分数从高到低
   - 否则按交易金额或笔数排序

## 6. 关键技术创新点

### 6.1 时序防泄露机制

**问题**：传统机器学习容易产生时间泄露（用未来信息预测过去）

**创新**：
1. **严格半开区间**：特征生成使用 `[as_of - lookback, as_of)`，绝不包含观察时点之后的数据
2. **标签可得时间分离**：区分 `risk_event_at`（预测目标）和 `label_available_at`（训练可见性）
3. **训练模式标记**：
   - `temporal`：严格时序训练，`production_eligible=true`
   - `retrospective_static`：静态回溯实验，`production_eligible=false`
4. **上线阻断机制**：缺少 `label_available_at` 时，系统拒绝生产模型训练

**业界对比**：
- 许多竞赛方案忽略时间泄露，导致线上效果远低于离线
- 本方案从架构层面强制时序安全，可直接部署生产

### 6.2 版本化管理

**创新**：
1. **内容寻址**：每个产物版本ID由内容哈希生成（类似Git）
2. **不可变性**：一旦生成，版本内容永不改变
3. **完整血缘**：评分 → 模型 → 特征 → 数据，全链路可追溯
4. **确定性保证**：相同输入必然产生相同版本ID

**业务价值**：
- 支持模型回滚：发现问题可立即切换至历史版本
- 支持A/B测试：多个模型版本并行评分对比
- 支持审计合规：任何决策可回溯至具体数据和模型

### 6.3 可审计架构

**创新**：
1. **证据引用源ID**：报告中的交易ID可回溯至源系统
2. **不虚构路径**：缺少交易的账户不会被强行生成链路
3. **人工复核工作流**：
   - 双人独立复核
   - 冲突自动识别
   - 强制仲裁流程
4. **只读服务**：模型输出仅用于辅助决策，不自动执行止付或冻结

**合规对齐**：
- 符合金融监管对可解释性的要求（逻辑回归系数可读）
- 支持案件追溯（证据包哈希不可变）
- 保护数据隐私（账户ID脱敏，敏感字段不写日志）

### 6.4 确定性证据生成

**创新**：
1. **时序路径搜索**：自研算法保证时间单调性+金额连续性
2. **证据分级**：A/B/C三级，明确哪些可作为案件证据
3. **完整性验收**：结构一致性、证据覆盖、Markdown匹配多维度检查
4. **人机协同**：系统生成证据包，人工复核确认，双重保障

**与传统方案对比**：
- 传统：黑盒模型输出分数，缺乏证据链
- 本方案：分数+行为+交易+路径，多维度可验证证据
