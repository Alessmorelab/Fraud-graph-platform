# 任务四：可审计研判报告与 Agent 辅助分析

## 1. 交付目标

任务四要求把模型结果、行为证据、交易证据和图结构证据组织成可读、可复核、可追溯的报告。本项目采用“结构化证据包 + 确定性报告模板 + 受约束 Agent”三层实现：报告结论只能来自证据包，Agent 只能在证据白名单内补充中文解释。

## 2. 报告生成

每个账户报告包含风险摘要、结构化证据、关键资金链路、异常资金流向模式、局限性、辅助处置建议和使用边界。正文展示风险最高的五条路径，其余路径进入附录；每条路径保留 `path_id` 和源 `transaction_id`，每个模式保留 `pattern_id`、交易 ID 和关联账户 ID。英文代码仅作为审计标识，展示层全部使用中文。

报告由 `src/fraud_graph/evidence/render.py` 生成，案例包通过 `fraud-graph export-case-samples` 生成，精确渲染匹配由 `fraud-graph accept-task4` 验收。案例真值尚未由赛事方提供，因此系统不计算同案关联命中率；五个典型案例已经完成双人独立人工复核，自动预检查没有被冒充为人工结论。

## 3. 任务四验收口径

当前案例包应满足：五个典型案例、每份报告至少两类证据、结构化证据与报告结论一致、报告字段完整、生成文本与模板精确匹配。离线验收输出 `task4_acceptance.json`，并记录案例版本、数据版本、模型版本和证据包哈希。

## 4. Agent 辅助分析

风险工作台的“研判助手”允许审核员围绕当前账户提问。Agent 可调用六个只读工具：风险摘要、结构化证据、可疑路径、关联账户、资金模式和报告边界。响应包含答案、研判状态、引用、工具轨迹、局限性、人工建议、证据包 SHA-256、模型/数据版本和校验状态。

DeepSeek 接入使用 `https://api.deepseek.com/chat/completions` 的 Tool Calls 协议。默认不开启外部数据发送；审核员可在研判助手中输入 Key、确认外发授权并创建 30 分钟临时内存会话，也可由受控部署通过 `.env` 固定配置。无 Key、网络错误、工具越权、协议错误或引用校验失败时自动回退到确定性中文摘要。临时 Key 不写入浏览器存储、项目文档、报告、日志或证据包。

## 5. 业务边界

风险分数是人工核查优先级，不是涉诈事实认定；没有交易证据时不能断言存在资金链。Agent 不执行冻结、止付、上报、人工签名、证据修改或任何不可逆业务动作，所有后续处置必须进入银行既有授权审批流程。

## 6. 局限与后续

当前标签发生时间缺失，任务一和任务二属于静态回溯实验，图特征评估包含传导信息，且交易正样本极少。因此报告和 Agent 的 `production_eligible` 均为 `false`。待赛事方提供时间标签、更多交易样本和案件关联真值后，可重新训练时序模型、校准阈值，并补充真正的案例关联命中率评估。
