# 特征说明文档

## 概述

本文档详细说明用于欺诈风险识别模型的27个特征。特征基于184天观察窗口计算，分为两大类：**行为特征**（24个）和**画像特征**（3个）。

- **特征实现版本**: `asof-account-v3`
- **观察窗口**: 184天（约6个月）
- **模型版本**: `27e53f783dde8968`
- **特征版本**: `f86409807550d65e`

---

## 一、行为特征（24个）

行为特征反映账户在观察窗口内的交易行为模式，是反欺诈模型的核心特征。

### 1.1 基础交易量特征

#### 1. out_txn_count（支出交易笔数）

**定义**: 观察窗口内作为付款方的交易总笔数

**计算公式**:
```sql
count(*) FROM transactions WHERE payer_account_id = account_id
```

**业务含义**: 反映账户的支付活跃度。异常高的支出频率可能表明账户被用于批量转账或洗钱中转。

**取值范围**: [0, +∞)，连续型数值

**风险指示**: 
- 极高值：可能为"跑分账户"，用于快速分散资金
- 极低值：与高金额结合时可能为"养号"后的大额诈骗

---

#### 2. in_txn_count（收入交易笔数）

**定义**: 观察窗口内作为收款方的交易总笔数

**计算公式**:
```sql
count(*) FROM transactions WHERE payee_account_id = account_id
```

**业务含义**: 反映账户的收款活跃度。异常高的收款频率可能表明账户为资金汇聚点。

**取值范围**: [0, +∞)，连续型数值

**风险指示**:
- 极高值：可能为诈骗资金归集账户
- 短期内从零到高：可能为临时收款账户

---

#### 3. txn_count_total（总交易笔数）

**定义**: 支出和收入交易笔数之和

**计算公式**:
```sql
out_txn_count + in_txn_count
```

**业务含义**: 综合反映账户整体活跃度，是判断账户是否为"中转账户"的关键指标。

**取值范围**: [0, +∞)，连续型数值

**风险指示**: 极高的总交易量结合短观察期可能表明账户被操控进行快速资金流转

---

### 1.2 交易对手特征

#### 4. out_counterparty_count（支出交易对手数）

**定义**: 观察窗口内收款方账户的去重计数

**计算公式**:
```sql
count(DISTINCT payee_account_id) WHERE payer_account_id = account_id
```

**业务含义**: 反映支付对象的分散程度。高对手数表明资金分散转移。

**取值范围**: [0, +∞)，连续型数值

**风险指示**: 高对手数 + 高交易频率 = 典型的资金分散洗钱模式

---

#### 5. in_counterparty_count（收入交易对手数）

**定义**: 观察窗口内付款方账户的去重计数

**计算公式**:
```sql
count(DISTINCT payer_account_id) WHERE payee_account_id = account_id
```

**业务含义**: 反映收款来源的分散程度。高对手数可能表明账户为多人转账目标。

**取值范围**: [0, +∞)，连续型数值

**风险指示**: 大量小额收款（高对手数 + 多笔小额）可能为网络赌博收款或诈骗分赃

---

#### 6. counterparty_count_total（总交易对手数）

**定义**: 支出和收入交易对手的总数（非去重和）

**计算公式**:
```sql
out_counterparty_count + in_counterparty_count
```

**业务含义**: 综合反映账户交易网络的广度。

**取值范围**: [0, +∞)，连续型数值

**风险指示**: 对手数与交易笔数的比值异常（过高或过低）都值得关注

---

### 1.3 活跃度特征

#### 7. out_active_days（支出活跃天数）

**定义**: 观察窗口内有支出交易的天数（按本地时间去重）

**计算公式**:
```sql
count(DISTINCT CAST(event_time_local AS DATE)) WHERE payer_account_id = account_id
```

**业务含义**: 反映支出行为的时间分散度。连续多日活跃表明账户持续使用。

**取值范围**: [0, 184]，连续型数值

**风险指示**: 短期内高活跃度（如7天内每天都有交易）可能为操控账户

---

#### 8. in_active_days（收入活跃天数）

**定义**: 观察窗口内有收入交易的天数

**计算公式**:
```sql
count(DISTINCT CAST(event_time_local AS DATE)) WHERE payee_account_id = account_id
```

**业务含义**: 反映收款行为的时间分散度。

**取值范围**: [0, 184]，连续型数值

**风险指示**: 收入集中在少数几天但金额巨大可能为诈骗资金快速转入

---

### 1.4 金额特征

#### 9. out_amount_abs_sum（支出金额总和）

**定义**: 观察窗口内所有支出交易金额绝对值的总和

**计算公式**:
```sql
sum(abs(amount)) WHERE payer_account_id = account_id
```

**业务含义**: 反映账户的总支出规模。

**取值范围**: [0, +∞)，连续型数值

**风险指示**: 与账户历史行为或客户类型不匹配的巨额支出

---

#### 10. in_amount_abs_sum（收入金额总和）

**定义**: 观察窗口内所有收入交易金额绝对值的总和

**计算公式**:
```sql
sum(abs(amount)) WHERE payee_account_id = account_id
```

**业务含义**: 反映账户的总收入规模。

**取值范围**: [0, +∞)，连续型数值

**风险指示**: 短期内大额收入可能为诈骗所得

---

#### 11. amount_abs_total（总交易金额）

**定义**: 支出和收入金额总和（绝对值）

**计算公式**:
```sql
out_amount_abs_sum + in_amount_abs_sum
```

**业务含义**: 综合反映账户的资金流动规模。

**取值范围**: [0, +∞)，连续型数值

**风险指示**: 异常高的资金吞吐量是洗钱的典型特征

---

#### 12. out_amount_max（最大单笔支出）

**定义**: 观察窗口内单笔支出交易的最大金额（绝对值）

**计算公式**:
```sql
max(abs(amount)) WHERE payer_account_id = account_id
```

**业务含义**: 反映账户的最大单次支付能力。

**取值范围**: [0, +∞)，连续型数值

**风险指示**: 突然出现的大额单笔支出可能为账户被盗后的转账

---

#### 13. in_amount_max（最大单笔收入）

**定义**: 观察窗口内单笔收入交易的最大金额（绝对值）

**计算公式**:
```sql
max(abs(amount)) WHERE payee_account_id = account_id
```

**业务含义**: 反映账户接收的最大单笔金额。

**取值范围**: [0, +∞)，连续型数值

**风险指示**: 与历史模式不符的大额收入可能为诈骗转入

---

#### 14. net_flow_amount（净流入金额）

**定义**: 收入金额总和减去支出金额总和

**计算公式**:
```sql
in_amount_abs_sum - out_amount_abs_sum
```

**业务含义**: 反映账户在观察期内的资金净流向。

**取值范围**: (-∞, +∞)，连续型数值

**风险指示**:
- 大额正值：可能为资金沉淀账户或最终受益账户
- 接近零：可能为典型的中转账户（"快进快出"）

---

### 1.5 比率特征

#### 15. in_out_count_ratio（收支笔数比）

**定义**: 收入交易笔数与支出交易笔数的比值（加1平滑）

**计算公式**:
```sql
(in_txn_count + 1.0) / (out_txn_count + 1.0)
```

**业务含义**: 反映收支行为的平衡性。比值偏离1表明明显的单向行为。

**取值范围**: (0, +∞)，连续型数值

**风险指示**:
- 远大于1：可能为收款专用账户
- 远小于1：可能为支付专用账户
- 极端值结合其他特征可识别"收款后分散"模式

---

#### 16. in_out_amount_ratio（收支金额比）

**定义**: 收入金额与支出金额的比值（加1平滑）

**计算公式**:
```sql
(in_amount_abs_sum + 1.0) / (out_amount_abs_sum + 1.0)
```

**业务含义**: 从金额角度反映收支平衡性。

**取值范围**: (0, +∞)，连续型数值

**风险指示**: 与笔数比结合分析可识别"聚少成多"或"化整为零"的洗钱手法

---

### 1.6 时间模式特征

#### 17. night_txn_count（夜间交易笔数）

**定义**: 本地时间22:00-次日07:00之间的交易总笔数（收入+支出）

**计算公式**:
```sql
sum(CASE WHEN hour(event_time_local) < 7 OR hour(event_time_local) >= 22 
    THEN 1 ELSE 0 END)
```

**业务含义**: 反映非常规时段的交易行为。正常用户夜间交易较少。

**取值范围**: [0, +∞)，连续型数值

**风险指示**: 高比例夜间交易可能表明：
- 账户被远程操控（跨时区）
- 自动化脚本交易
- 异常操作避开监控高峰

---

#### 18. same_day_in_out_days（同日收支天数）

**定义**: 同一天既有收入又有支出的天数

**计算公式**:
```sql
count(days WHERE in_amount > 0 AND out_amount > 0)
```

**业务含义**: 反映"当日周转"行为的频次。

**取值范围**: [0, min(out_active_days, in_active_days)]，连续型数值

**风险指示**: 高频同日收支是中转账户的典型特征（"过账"）

---

#### 19. same_day_turnover_ratio_avg（同日周转率均值）

**定义**: 在有同日收支的日期，当日收支较小值与较大值的比值平均

**计算公式**:
```sql
avg(least(in_amount, out_amount) / greatest(in_amount, out_amount))
WHERE in_amount > 0 AND out_amount > 0
```

**业务含义**: 反映同日收支的完整性。接近1表示收入几乎全部支出。

**取值范围**: [0, 1]，连续型数值

**风险指示**: 高周转率（接近1）表明资金快速流转，几乎不留余额，是洗钱中转的关键信号

---

### 1.7 网络拓扑特征

#### 20. max_daily_fan_in（单日最大入度）

**定义**: 单日内向该账户转账的不同账户数的最大值

**计算公式**:
```sql
max(count(DISTINCT payer_account_id) per day)
```

**业务含义**: 反映账户作为"资金汇聚点"的最大强度。

**取值范围**: [0, +∞)，连续型数值

**风险指示**: 极高的单日入度（如一天内数十个账户转入）可能为：
- 网络赌博结算
- 诈骗团伙分赃
- 资金归集操作

---

#### 21. max_daily_fan_out（单日最大出度）

**定义**: 单日内从该账户转出到不同账户数的最大值

**计算公式**:
```sql
max(count(DISTINCT payee_account_id) per day)
```

**业务含义**: 反映账户作为"资金分发点"的最大强度。

**取值范围**: [0, +∞)，连续型数值

**风险指示**: 极高的单日出度表明资金快速分散，是洗钱的典型手法

---

### 1.8 异常行为标识

#### 22. negative_txn_count（负值交易笔数）

**定义**: 标记为负值（is_negative = true）的交易笔数

**计算公式**:
```sql
sum(CASE WHEN is_negative THEN 1 ELSE 0 END)
```

**业务含义**: 负值交易可能代表退款、冲正、或系统调账。

**取值范围**: [0, +∞)，连续型数值

**风险指示**: 异常高的负值交易可能表明：
- 刷单后退款
- 系统漏洞利用
- 异常操作尝试

---

#### 23. self_transfer_count（自转笔数）

**定义**: 付款人和收款人为同一账户的交易笔数

**计算公式**:
```sql
sum(CASE WHEN is_self_transfer THEN 1 ELSE 0 END) 
WHERE payer_account_id = account_id
```

**业务含义**: 自己给自己转账，可能为余额归集或测试操作。

**取值范围**: [0, +∞)，连续型数值

**风险指示**: 频繁自转可能为：
- 刷交易量
- 掩盖真实交易模式
- 制造虚假活跃度

---

#### 24. has_transactions（是否有交易）

**定义**: 观察窗口内是否有任何交易的二元标识

**计算公式**:
```sql
CASE WHEN txn_count_total > 0 THEN 1.0 ELSE 0.0 END
```

**业务含义**: 区分活跃账户和沉睡账户。

**取值范围**: {0.0, 1.0}，二元分类

**风险指示**: 长期沉睡后突然激活的账户可能为被盗账户或"养号"账户

## 二、画像特征（3个）

画像特征反映账户的静态属性，来源于账户主数据，不随观察窗口变化。

### 2.1 tenure_months（账龄月数）

**定义**: 账户开户至观察截止时间的月数

**数据来源**: `accounts.tenure_months`

**业务含义**: 反映账户的"可信度"基线。老账户通常风险较低。

**取值范围**: [0, +∞)，连续型数值

**风险指示**: 
- 新开户账户（0-3个月）：风险基线较高
- 新账户 + 高交易量 = 高风险信号
- 老账户突然行为异变可能为账户被盗

**所属类别**: 画像特征

---

### 2.2 region_code（地区编码）

**定义**: 账户注册或归属的地理区域编码

**数据来源**: `accounts.region_code`

**业务含义**: 地域因素可能与欺诈风险相关（某些地区欺诈高发）。

**取值范围**: 分类变量（具体编码取决于业务定义）

**风险指示**: 
- 模型可学习到特定地区的风险差异
- 结合交易对手地区可识别异常跨区交易

**所属类别**: 画像特征

---

### 2.3 customer_type（客户类型）

**定义**: 账户的客户类型分类（如个人/企业/商户等）

**数据来源**: `accounts.customer_type`

**业务含义**: 不同客户类型的正常交易模式差异巨大。

**取值范围**: 分类变量（具体类型取决于业务定义）

**风险指示**: 
- 个人账户出现企业级交易量属异常
- 模型可针对不同类型建立不同的风险基线

**所属类别**: 画像特征

## 三、特征组合与风险模式

### 3.1 典型风险模式识别

**中转账户模式**（"跑分"账户）:
- `same_day_in_out_days` 高
- `same_day_turnover_ratio_avg` 接近 1.0
- `net_flow_amount` 接近 0
- `txn_count_total` / `tenure_months` 比值异常高

**资金归集账户**:
- `max_daily_fan_in` 极高
- `in_out_count_ratio` 远大于 1
- `net_flow_amount` 大额正值
- `in_counterparty_count` 高

**资金分散账户**（洗钱最终阶段）:
- `max_daily_fan_out` 极高
- `in_out_count_ratio` 远小于 1
- `out_counterparty_count` 高

**异常操控账户**:
- `night_txn_count` / `txn_count_total` 比值高
- `tenure_months` 低 + `txn_count_total` 高
- `self_transfer_count` 异常高

### 3.2 特征重要性说明

基于模型训练结果（ROC AUC = 0.934），关键特征组合包括：
1. **同日周转特征组**：识别中转行为
2. **网络拓扑特征组**：识别资金流向异常
3. **时间模式特征组**：识别非人工操作
4. **账龄与行为匹配**：识别新账户异常活跃

## 四、数据处理说明

### 4.1 特征计算窗口
- **观察窗口**: 184天（约6个月）
- **截止时间**: `as_of` 参数指定（通常为最新交易时间 + 1微秒）
- **时间区间**: `[as_of - 184天, as_of)`

### 4.2 缺失值处理
- 所有数值特征使用 `coalesce(..., 0.0)` 处理
- 无交易账户的所有行为特征默认为 0
- 画像特征从账户主数据获取，不应存在缺失

### 4.3 时区处理
- `event_time_utc`: UTC标准时间，用于窗口过滤
- `event_time_local`: 本地时间，用于计算活跃天数和夜间交易

### 4.4 数值稳定性
- 比率特征使用 `+1.0` 平滑避免除零
- 金额使用 `abs()` 取绝对值确保非负

## 五、特征使用指南

### 5.1 模型训练
- 特征集名称: `combined`（行为 + 画像）
- 特征向量维度: 27
- 标准化: 建议使用 StandardScaler
- 分类特征编码: `region_code` 和 `customer_type` 需编码

### 5.2 特征监控
建议监控以下指标：
- 特征分布漂移（训练集 vs 生产集）
- 缺失率（应始终为0）
- 异常值比例（超出历史分位数）

### 5.3 特征更新
- 特征计算代码版本: `asof-account-v3`
- 特征定义变更需更新 `FEATURE_IMPLEMENTATION_VERSION`
- 变更将触发新的 `feature_version` 生成
